# Руководство по работе с репозиторием

## Общение
Сначала отвечайте кратко по существу, затем добавляйте необходимые пояснения. Говорите прямо; допустимы уместные шутки и критика решений. Код пишите развёрнуто, используя классические конструкции.

## Восстановление контекста
Перед работой прочитайте `Docs/PROJECT_CONTEXT.md`: там записаны назначение файлов, реализованные функции, ограничения и выполненные изменения. Исходное описание — `Docs/Описание_файлов_SmartHome.docx`; оно описывает замысел, а фактическую реализацию проверяйте по коду.

После каждой задачи обновляйте контекст: дата, что сделано, затронутые файлы, выполненные проверки и оставшиеся вопросы. Не отмечайте планы и непроверенные функции как завершённые. Сохраняйте актуальное состояние кратким, без переписывания всей переписки.

## Структура проекта и организация модулей
SmartHome — приложение Windows Forms для .NET Framework 4.8. Решение `SmartHome.sln` содержит один проект приложения — `SmartHome.csproj`.

- `Program.cs` запускает приложение; `Form1.cs` содержит демонстрационный интерфейс и обработчики событий.
- `Models/` содержит модели устройств, датчиков, комнат, сценариев, пользователей и перечисления.
- `Services/` содержит управление системой, проверку команд, обнаружение устройств и уведомления.
- `Data/DeviceRepository.cs` — заготовка для хранения данных; методы пока не реализованы.
- `Properties/` содержит метаданные сборки, настройки и ресурсы. `Form1.Designer.cs` и `Form1.resx` описывают разметку и ресурсы формы.
- `Docs/` содержит диаграммы, снимки экрана и документ Word; `SmartHome.cd` — диаграмма классов.

Каталоги `bin/`, `obj/` и `.vs/` содержат автоматически создаваемые файлы. Не редактируйте их как исходный код.

## Команды сборки и запуска
Используйте Windows и Visual Studio с компонентами разработки классических приложений .NET и пакетом нацеливания на .NET Framework 4.8. Выполняйте команды из корня репозитория в Developer PowerShell:

```powershell
msbuild SmartHome.sln /p:Configuration=Debug
msbuild SmartHome.sln /p:Configuration=Release
.\bin\Debug\SmartHome.exe
```

Первые две команды собирают отладочную и оптимизированную выпускную версии; третья запускает отладочную версию приложения. Для отладки откройте `SmartHome.sln` в Visual Studio и нажмите F5.

## Стиль кода и правила именования
Следуйте существующему стилю C#: отступы в четыре пробела, фигурные скобки на отдельных строках, PascalCase для типов и открытых членов, camelCase для параметров и закрытых полей. Используйте пространство имён `SmartHome`; размещайте каждый основной тип в отдельном файле с соответствующим именем. Сохраняйте шаблон `controlName_EventName` для обработчиков событий формы и русский язык интерфейса.

Размещайте бизнес-логику в моделях или сервисах. Меняйте разметку через конструктор Windows Forms. Явно добавляйте новые исходные файлы в `SmartHome.csproj` через элементы `<Compile Include="..." />`. Форматтер и линтер в проекте не настроены.

## Понятный код на C#
Пишите код так, чтобы его мог прочитать и объяснить начинающий программист. Простота не отменяет корректность, проверку входных данных и обработку ошибок.

- Не используйте тернарный оператор `?:`. Ветвления оформляйте через полный `if/else`.
- Всегда ставьте фигурные скобки у условий и циклов, даже для одной строки.
- Предпочитайте явные типы (`Room room`, `int level`) вместо `var`, понятные имена и промежуточные переменные.
- Предпочитайте обычные `for`/`foreach` и отдельные методы сложным цепочкам LINQ, вложенным выражениям и компактным лямбдам. Обработчики событий оформляйте именованными методами, когда это упрощает чтение.
- Пишите короткие поясняющие комментарии на русском там, где смысл неочевиден. Не вводите сложные абстракции без необходимости.
- Применяйте правила к новому и изменяемому вручную коду. Не переписывайте весь проект или автоматически созданные файлы только ради стиля.

Вместо `string result = number % 2 == 0 ? "чётное" : "нечётное";` пишите:

```csharp
string result;
if (number % 2 == 0)
{
    result = "чётное";
}
else
{
    result = "нечётное";
}
```

## Рекомендации по тестированию
Фреймворк автоматизированного тестирования, тестовый проект и минимальный порог покрытия не настроены. После сборки вручную проверяйте изменение яркости, потерю связи с контроллером, оповещение о протечке, аварийное закрытие крана, сброс и обновление журнала. Фиксируйте выполненные проверки. Новые автоматизированные тесты размещайте в отдельном тестовом проекте; используйте понятные имена, например `SetBrightness_OutOfRange_Throws`.

## Коммиты и запросы на слияние
Общий репозиторий: https://github.com/EEEEgggoor/SmatHome_KPO, основная ветка — `main`. Локальная папка находится под контролем Git; `origin` указывает на общий репозиторий, `main` отслеживает `origin/main`. Исходная история и `LICENSE` сохранены. Первая версия приложения фиксируется локально; отправка на GitHub выполняется отдельным шагом. Через подключение GitHub подтверждены права чтения и записи аккаунта `hokkkage`. Исторические соглашения о коммитах не установлены. Используйте короткие заголовки с указанием действия, например `Исправить обработку потери связи с контроллером`. Посвящайте каждый коммит одной задаче. В запросе на слияние описывайте изменения поведения, указывайте связанные задачи и выполненные проверки. Для изменений интерфейса прикладывайте снимки экрана.
