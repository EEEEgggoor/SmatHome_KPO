# Руководство по работе с репозиторием

## Общение и восстановление контекста
Сначала отвечайте кратко по существу, затем добавляйте пояснения. Говорите прямо; допустимы уместные шутки и критика решений.

Перед каждой задачей читайте `Docs/PROJECT_CONTEXT.md` и проверяйте текущие файлы. После задачи обновляйте контекст: что сделано, какие файлы изменены, какие проверки выполнены, что осталось и следующий шаг. Не отмечайте планы, шаблоны и непроверенные функции как готовые.

## Назначение и рабочая папка
SmartHome — Android-приложение на Java с XML-интерфейсом и Android Views. Рабочая папка Android: `D:\AndroidStudioProjects\SmartHome\SmartHome_App`. Корень Git: `D:\AndroidStudioProjects\SmartHome`; ветка приложения — `SmartHome_App`. Текущий объём задан HTML-макетом Haven `smart-home-demo-1.html`: только функции, перечисленные в `Docs/PROJECT_CONTEXT.md`. Старый C#-проект — историческая справка; не переносите из него сценарии, роли, журнал и аварийную автоматику без отдельного запроса. План будущих файлов не считать выполненной реализацией. Файлы `*.gradle.kts` описывают сборку и не меняют язык приложения.

Уточнение пользователя: названия комнат и устройств можно менять. «⋮» на карточке устройства открывает переименование. В Room и Device имя изменяемое через проверяемый setName; идентификаторы остаются постоянными. Не исключайте эту функцию из-за отсутствующего обработчика в HTML.

Удаление комнаты вместе с привязанными устройствами включено в план по уточнению пользователя. Логику удаления по id размещайте в HomeRepository; модели Room/Device не удаляют себя. Подтверждение и меню выполняет первый участник. Отдельное удаление устройства предложено как пункт его меню; удаление комнаты должно быть явно обозначено.

Начальное состояние устройства получать из данных интеграции. online обозначает доступность, poweredOn — питание; это разные признаки. Конструкторы принимают известное состояние, неизвестное питание не заменяйте значением false. Создание модели не должно отправлять команды оборудованию.

## Наша роль — второй участник
Пользователь и ассистент работают в роли второго участника: Java-классы, модели, данные и логика приложения. Наша область — `model/`, `data/`, `service/`, `integration/`: комнаты и устройства, HomeRepository, DemoDataFactory, DeviceControlService, ControllerGateway и DemoControllerGateway, а также описание методов для интеграции.

Первый участник отвечает за Activity, адаптеры, диалоги и XML-интерфейс; третий — за реальную связь с контроллерами. Без отдельного поручения не изменяйте их части. Согласовывайте доступные интерфейсу методы и данные. Текущий формат — пошаговое обучение: по запросу пользователя объясняйте, где создать файл, давайте полный простой код, способ проверки и ожидаемый результат. Начинаем с Room; не отмечайте выданный код реализованным, пока он не появился в проекте. Если пользователь просит инструкцию, не создавайте Java-файлы за него автоматически.

## Граница работы с контроллерами
Два участника готовят приложение, третий реализует связь с настоящими контроллерами. Планируйте обычный Java-интерфейс ControllerGateway и отдельную демонстрационную реализацию. Экраны работают с данными и результатами команд; USB/Wi-Fi и прошивку не реализовывайте в рамках задач команды приложения. Контракт команд, показаний и ошибок согласуйте перед интеграцией. Подробности — в Docs/PROJECT_CONTEXT.md.

## Структура
- `app/src/main/java/com/example/smarthome/` — исходники Java; сейчас содержит `MainActivity.java`.
- `app/src/main/res/` — разметка, строки, темы, цвета и изображения.
- `app/src/main/AndroidManifest.xml` — приложение, экраны и разрешения.
- `app/src/test/` — локальные тесты JUnit; `app/src/androidTest/` — тесты на устройстве.
- `app/build.gradle.kts`, `gradle/libs.versions.toml` — настройки Android и зависимости.
- `Docs/PROJECT_CONTEXT.md` — состояние проекта, решения и журнал разработки.

## Простой и развёрнутый Java-код
Пишите код, понятный начинающему: отступы в четыре пробела, фигурные скобки на отдельных строках, явные типы, понятные имена и промежуточные переменные. Классы называйте PascalCase, методы и переменные — camelCase, ресурсы — snake_case.

Не используйте тернарный оператор `?:`, компактные лямбды, Stream API и сложные цепочки выражений. Предпочитайте полные `if/else`, обычные циклы, отдельные методы и явно объявленные обработчики. Всегда ставьте фигурные скобки. Например:

```java
String result;
if (number % 2 == 0)
{
    result = "чётное";
}
else
{
    result = "нечётное";
}
```

Применяйте правила к новому и изменяемому коду без массового переписывания шаблона. Комментарии пишите по-русски, когда смысл неочевиден. Сохраняйте корректную обработку ошибок. Строки интерфейса храните в `strings.xml`. Логику устройств отделяйте от Activity; сетевые операции выполняйте вне главного потока. Не вводите сложные абстракции без необходимости.

## Сборка и проверки
Используйте Android Studio и Gradle Wrapper из корня проекта:

```powershell
.\gradlew.bat :app:assembleDebug
.\gradlew.bat :app:testDebugUnitTest
.\gradlew.bat :app:connectedDebugAndroidTest
.\gradlew.bat :app:lintDebug
```

Команды собирают APK, запускают локальные тесты, тесты на устройстве/эмуляторе и Android Lint соответственно. Совместимость JDK и SDK сверяйте с настройками проекта. Шаблонные тесты не подтверждают функции умного дома. Фиксируйте реальные результаты; не называйте непройденные проверки успешными.
