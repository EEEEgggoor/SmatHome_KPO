# Структура работы над интерфейсом SmartHome

## Проект и распределение работы
Общий репозиторий: https://github.com/EEEEgggoor/SmatHome_KPO. Ветка приложения — SmartHome_App. В Android Studio открываем папку SmartHome_App внутри репозитория, где находится settings.gradle.kts. Язык — Java, интерфейс — XML и Android Views.

Этот документ предназначен напарнику, который делает интерфейс. По ранее принятому распределению он первый участник; автор моделей — второй. Чтобы избежать путаницы, ниже используются названия ролей.

- Участник интерфейса: MainActivity, адаптеры, диалоги, XML, меню, изображения, оформление и обновление экрана.
- Участник логики: модели, база SQLite через Room, репозиторий, управление устройствами, демонстрационная интеграция и DeviceValueFormatter.
- Участник по оборудованию: реальный обмен с контроллерами и прошивка, через согласованный интерфейс ControllerGateway.

## Текущее состояние
В исходниках существуют MainActivity и пять моделей: Room, Device, LightDevice, RelayDevice, WaterDevice. Главный экран пока шаблонный. Ниже приведён план будущих файлов, а не готовый API. Репозиторий, база, сервисы и полноценные экраны ещё не реализованы. DeviceValueFormatter и его ресурсы реализованы; 6 октября подтверждены 22 теста на эмуляторе.

## Java-файлы участника интерфейса
Пути относительно app/src/main/java/com/example/smarthome:

```text
MainActivity.java
ui/
├── adapter/
│   ├── RoomAdapter.java
│   └── DeviceAdapter.java
└── dialog/
    ├── LightControlDialog.java
    ├── RelayControlDialog.java
    ├── WaterControlDialog.java
    ├── AddRoomDialog.java
    ├── RenameRoomDialog.java
    ├── RenameDeviceDialog.java
    └── ConnectDeviceDialog.java
```

- MainActivity: список устройств, выбор комнаты, счётчики и открытие диалогов. Список «Все устройства» — режим фильтрации, а не отдельная комната в базе.
- RoomAdapter: вывод комнат, выбор комнаты и вызов её меню действий.
- DeviceAdapter: карточки света, реле и воды, открытие управления и меню устройства.
- LightControlDialog: включение света, яркость 0–100, относительная температура света 0–100. Это не Кельвины.
- RelayControlDialog: включённое состояние реле и его доступность.
- WaterControlDialog: уровень воды, температура, статус уровня, время измерения и переключатель клапана.
- AddRoomDialog: ввод имени комнаты, сохранение и вывод ошибок проверки.
- RenameRoomDialog и RenameDeviceDialog: текущее имя, редактирование, сохранение или отмена. При необходимости можно сделать один общий диалог вместо двух.
- ConnectDeviceDialog: интерфейс подключения ESP32 по USB, ввод SSID/пароля Wi-Fi, этапы подключения и результат. Реальный транспорт выполняет участник по оборудованию; источник типа/имени/комнаты нового устройства ещё нужно согласовать.

## Форматирование — часть участника логики
Реализован отдельный файл presentation/DeviceValueFormatter.java. Модели сохраняют числовые значения и состояния; форматтер возвращает готовые подписи, интерфейс устанавливает их в TextView.

Доступные методы возвращают String; создавать через new DeviceValueFormatter(getResources()) внутри Activity:

| Метод | Данные | Пример подписи |
| --- | --- | --- |
| formatWaterLevel(Integer value) | Проценты или null | «64 %», «Нет данных» |
| formatTemperature(Double value) | Градусы или null | «22,40 °C», «Нет данных» |
| formatLastUpdate(Long value) | Unix-время в миллисекундах или null | «Только что» при возрасте 0–59999 мс; иначе дата/время dd.MM.yyyy HH:mm:ss; null — «Нет данных» |
| formatValveState(Boolean value) | Открыт, закрыт или неизвестно | «Открыт», «Закрыт», «Нет данных» |
| formatOnlineState(boolean value) | Доступность | «В сети», «Не в сети» |
| formatPowerState(boolean value) | Состояние питания нагрузки | «Включено», «Выключено» |
| formatBrightness(int value) | Проценты яркости | «75 %» |

Пользовательские строки хранить в Android-ресурсах; имена ресурсов согласовать между участниками. Округление температуры выполняется для подписи, исходное число в модели сохраняется. Цвета, иконки, индикаторы, доступность кнопок и обновление экрана остаются задачей интерфейса. Пороги уровня воды и расчёт levelStatus не относятся к форматтеру; правила пока не определены.

## Как соединяем интерфейс и логику
- Комнаты и устройства интерфейс получает через будущий HomeRepository. Добавление, переименование и удаление передаёт ему, не выполняет SQL из Activity.
- Команды включения, настройки света и клапана передаёт будущему DeviceControlService. Сигнатуры и способ асинхронного возврата результата ещё согласуем; не создавать фиктивные вызовы несуществующих методов.
- Изменение поля модели само по себе не управляет оборудованием. После команды нужно показывать ожидание, а подтверждённое состояние обновлять по результату интеграции. Ошибка команды не должна выглядеть как успех.
- online и poweredOn независимы. При потере связи последнее состояние не превращается в false: оно становится устаревшим и должно быть обозначено в интерфейсе.
- Nullable-показания означают отсутствие данных. Нельзя показывать их как 0 или закрытый клапан. Переключатель неизвестного состояния не должен создавать впечатление подтверждённого положения клапана.
- Подпись «Контакт замкнут» нельзя выводить из poweredOn без согласованной физической схемы. Пока использовать «Реле включено/выключено».
- Получение данных из базы и работа с контроллерами выполняются вне главного потока; обновление Views — в главном потоке.

## Порядок работы и совместные файлы
Сначала главный экран и карточки, затем диалоги управления, действия комнат/устройств и подключение. Пока логика не готова, использовать явно демонстрационные данные; не выдавать макет за управление реальным оборудованием.

Перед работой получать изменения общей ветки, после небольшой законченной задачи создавать коммит и отправлять его. Изменения strings.xml, Gradle и AndroidManifest.xml заранее согласовывать: эти файлы могут понадобиться обоим. Не использовать force push в общей ветке. Код писать развёрнуто: явные типы, полный if/else, фигурные скобки у всех условий и циклов.
## Актуальный API форматтера, 6 октября 2026
Все перечисленные методы реализованы. Дополнительно доступны formatLevelStatus(String) — возвращает обрезанный статус или «Нет данных», и formatLightTemperature(int) — процент относительной температуры света 0–100. Конструктор принимает Resources, строки находятся в res/values/device_values.xml. Результат проверки: 22 успешных теста на эмуляторе.

formatLastUpdate(Long) получает текущее время самостоятельно. Значения — Unix-миллисекунды. При возрасте от 0 до 59999 мс возвращает «Только что», иначе дату и время dd.MM.yyyy HH:mm:ss в часовом поясе телефона. Перегрузка с заданным currentTime нужна тестам; из UI вызывать метод с одним аргументом. Пока окно видно, интерфейс должен периодически обновлять подпись, чтобы «Только что» не оставалось навсегда. Остановить обновление при закрытии окна.
